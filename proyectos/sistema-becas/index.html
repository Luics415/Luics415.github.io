Sistema de Becas

Plataforma PHP/MVC para gestionar convocatorias, solicitudes y validación documental.

Revisar repositorio

El proyecto

Sistema de Becas digitaliza el proceso de solicitud de becas de una institución educativa: desde la publicación de la convocatoria hasta la resolución final de cada expediente.

Arquitectura

Construido con PHP siguiendo el patrón MVC: controladores por módulo, modelos con acceso a MySQL y vistas reutilizables. La autenticación y los permisos se resuelven por rol en cada controlador.

Módulos principales

Gestión de convocatorias, registro y seguimiento de solicitudes, validación documental con historial de estatus, y administración de usuarios y permisos.

Puntos destacados

  • Roles diferenciados: alumno, revisor y administrador
  • Carga y validación de documentos por solicitud
  • Ciclo completo de convocatoria: publicación, solicitud, revisión y resultado

Arquitectura técnica

La aplicación organiza solicitudes HTTP en controladores, reglas de negocio en servicios o modelos y presentación en vistas. El acceso a datos queda encapsulado, mientras autenticación y autorización se evalúan antes de permitir transiciones sobre expedientes o documentos.

Flujo de ejecución

  • La ruta recibe una petición y valida sesión, rol y datos de entrada.
  • El controlador delega la operación al dominio y el repositorio ejecuta la persistencia.
  • La respuesta presenta el nuevo estado y conserva información suficiente para seguimiento.

Decisiones de ingeniería

  • Separar validación, negocio y HTML reduce controladores difíciles de mantener.
  • Representar los estados como transiciones permitidas evita cambios arbitrarios de un expediente.
  • Aplicar permisos en servidor impide depender únicamente de controles ocultos en la interfaz.

Compromisos y límites

  • MVC aporta estructura clara, aunque añade capas a operaciones pequeñas.
  • La validación estricta protege integridad, pero debe comunicar errores sin perder datos del formulario.
  • Los archivos adjuntos simplifican el expediente digital, pero requieren límites, nombres seguros y control de acceso.

La búsqueda limita el acceso a usuarios activos, usa parámetros en vez de interpolar el correo y verifica el hash mediante la API nativa de PHP.

Procedencia: Código real del repositorio · commit 1e54016 · models/UsuarioModel.php, líneas 10–29.

public function findByEmail(string $email): ?array
{
    $stmt = $this->db->query(
        'SELECT u.*, r.nombre AS rol_nombre
         FROM usuarios u
         JOIN roles r ON r.id = u.rol_id
         WHERE u.email = ? AND u.activo = 1
         LIMIT 1',
        [$email]
    );
    $row = $stmt->fetch();
    return $row ?: null;
}

public function autenticar(string $email, string $password): ?array
{
    $user = $this->findByEmail($email);
    if (!$user) return null;
    if (!password_verify($password, $user['password_hash'])) return null;
    return $user;
}

public function enviar(int $id, int $usuarioId): bool
{
    $stmt = $this->db->query(
        "UPDATE solicitudes SET estado = 'enviada', fecha_envio = NOW()
         WHERE id = ? AND usuario_id = ? AND estado = 'borrador'",
        [$id, $usuarioId]
    );
    if ($stmt->rowCount() > 0) {
        $this->registrarHistorial(
            $id, 'borrador', 'enviada',
            'Solicitud enviada por el alumno.', $usuarioId
        );
        return true;
    }
    return false;
}

function validateApplication(array $input): array
{
    $name = trim((string) ($input['name'] ?? ''));
    $program = trim((string) ($input['program'] ?? ''));

    if ($name === '' || $program === '') {
        throw new InvalidArgumentException('Faltan campos requeridos.');
    }

    return ['name' => $name, 'program' => $program];
}
