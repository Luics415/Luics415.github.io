Palabra y Oración

Biblia en español, Santo Rosario guiado y oraciones católicas con lectura por voz.

Revisar repositorioAbrir demo

Objetivo

Palabra y Oración centraliza lectura bíblica, oración y seguimiento del Santo Rosario en una interfaz tranquila, accesible y adaptable a computadora o teléfono, sin exigir registro ni infraestructura de servidor.

Arquitectura técnica

La interfaz usa React y TanStack Router con módulos divididos por ruta. Los 66 libros se almacenan como JSON y se solicitan bajo demanda; favoritos y progreso viven en localStorage, mientras Web Speech API genera la lectura con las voces disponibles en cada dispositivo.

Calidad, privacidad y publicación

Es una aplicación estática desplegada automáticamente en GitHub Pages. No utiliza cuentas, backend ni analítica propia; los datos de uso permanecen en el navegador. El diseño responde a dispositivos móviles y respeta la preferencia de movimiento reducido.

Puntos destacados

  • 66 libros y 1,189 capítulos bíblicos cargados bajo demanda
  • 38 oraciones, búsqueda, categorías, favoritos y lectura por voz
  • Rosario guiado con misterios por día, cuentas interactivas y progreso local

Arquitectura técnica

Una interfaz web estática separa contenido, estado de presentación y servicios del navegador. La navegación o el desplazamiento producen un estado normalizado; persistencia local y caché sin conexión se mantienen detrás de adaptadores para no acoplar la experiencia visual a una API remota.

Flujo de ejecución

  • La interacción del visitante genera una posición, selección o intención de navegación.
  • Una capa de estado normaliza la entrada y decide qué contenido, escena o progreso mostrar.
  • La vista renderiza el resultado y conserva únicamente las preferencias o avances necesarios en el dispositivo.

Decisiones de ingeniería

  • Modelar el contenido como datos permite reutilizar la misma fuente en búsqueda, navegación y vistas detalladas.
  • Derivar el estado visual de una entrada normalizada facilita reproducir la experiencia hacia adelante y hacia atrás.
  • Mantener la persistencia en el navegador reduce infraestructura y evita exigir una cuenta al visitante.

Compromisos y límites

  • La operación sin backend mejora privacidad y disponibilidad, pero limita sincronización entre dispositivos.
  • Las escenas ricas aumentan el impacto visual, aunque exigen presupuestos estrictos de peso y movimiento.
  • Una caché agresiva acelera visitas posteriores, pero requiere versionado cuidadoso para no servir recursos antiguos.

Captura de rutas profundas desde 404

JavaScript · HTML

Convierte una ruta que GitHub Pages no reconoce en un parámetro seguro y devuelve al punto de entrada de la SPA sin perder query ni hash.

Procedencia: Código real del artefacto público · commit 38beb16 · 404.html, líneas 9–16.

<script>
  (function () {
    var base = '/palabra-y-oracion/';
    var route = location.pathname.slice(base.length - 1)
      + location.search
      + location.hash;
    location.replace(base + '?__route=' + encodeURIComponent(route));
  }());
</script>

Restauración de ruta al cargar la SPA

JavaScript · HTML

Recupera la ruta codificada, reemplaza la URL sin recargar el documento y emite popstate para devolver el control al router del cliente.

Procedencia: Código real del artefacto público · commit 38beb16 · index.html, líneas 11–23. El retardo fijo es una solución pragmática pendiente de una señal explícita del router.

<script>
  (function () {
    var params = new URLSearchParams(location.search);
    var route = params.get('__route');
    if (!route) return;

    window.addEventListener('load', function () {
      setTimeout(function () {
        history.replaceState({}, '', '/palabra-y-oracion' + decodeURIComponent(route));
        dispatchEvent(new PopStateEvent('popstate'));
      }, 750);
    });
  }());
</script>

Patrón técnico relacionado: Progreso normalizado de una experiencia guiada

TypeScript

Ejemplo conceptual de cómo convertir una posición de desplazamiento en un estado estable entre 0 y 1.

Procedencia del ejemplo: Código representativo. Reconstrucción conceptual basada en el objetivo y stack públicos del proyecto; no es un extracto literal del repositorio.

type ProgressInput = { scrollY: number; start: number; end: number };

export function deriveProgress(input: ProgressInput) {
  const distance = Math.max(input.end - input.start, 1);
  const offset = input.scrollY - input.start;
  const raw = offset / distance;
  const progress = Math.min(1, Math.max(0, raw));

  return {
    progress,
    complete: progress === 1,
  };
}
